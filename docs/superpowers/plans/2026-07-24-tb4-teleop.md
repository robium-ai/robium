# tb4-teleop Phase 1 (Navigation) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Drive a real TurtleBot 4 from a browser (Foxglove Studio teleop panel) over Wi-Fi, with live `/scan` and status feedback — no ROS on the Mac.

**Architecture:** `foxglove_bridge` runs on the robot exposing a WebSocket on `192.168.0.100:8765`; it bridges the Pi's CycloneDDS topics over localhost. A committed Foxglove layout (Teleop + 3D + indicator panels) connects from the browser. Repo app is bootstrapped from `apps/nav-trial` conventions.

**Tech Stack:** ROS 2 Humble, `ros-humble-foxglove-bridge`, Foxglove Studio (browser), bash + `curl`/`openssl` (WS handshake probe), SSH to robot for HIL checks.

## Global Constraints

- **Robot:** TurtleBot 4, ROS 2 **Humble**, Ubuntu 22.04 aarch64, CycloneDDS, `ROS_DOMAIN_ID=0`, no namespace.
- **Robot IP:** `192.168.0.100` (SSH `ubuntu@192.168.0.100`, key installed, sudo pw `turtlebot4`). mDNS inactive — always use the IP, never `ubuntu.local`.
- **Mac IP:** `192.168.0.101` (en5 wired to RobotWiFi router LAN1). Mac stays ROS-free.
- **`/cmd_vel` type:** `geometry_msgs/msg/Twist` (plain Twist — NOT TwistStamped).
- **Bridge port:** `8765`. WebSocket subprotocol: verify against the installed package version — `foxglove_bridge` ≥3.x (SDK) uses `foxglove.sdk.v1`; older uses `foxglove.websocket.v1` (see Task 3).
- **Split-DDS:** the Create 3 base subscribes to `/cmd_vel` in a separate FastDDS realm; Pi-side `ros2 topic info` shows 0 subscribers even when working. **Motion is confirmed only empirically** (Task 6).
- **Safety:** the robot physically moves. Any step that can cause motion (Task 6) requires the robot **undocked, on clear floor, human supervising**. All automated smoke steps publish only **zero** Twist.
- **Smoke is hardware-in-the-loop:** requires the robot powered and on RobotWiFi; not CI-runnable without hardware. Documented and accepted.

### Task 0: One-time bridge install on the robot (prerequisite, no repo artifact)

Installs `ros-humble-foxglove-bridge` on the robot. RobotWiFi has no internet, so this uses the cable + Internet Sharing path. Produces robot state, not a committed file — but every later task depends on it.

**Files:** none committed. Robot-side package install only.

- [ ] **Step 1: Re-cable + enable Internet Sharing.** Physically connect the Ethernet cable robot↔Mac (direct). On the Mac: System Settings → General → Sharing → Internet Sharing → share from **Wi-Fi**, to **USB 10/100/1000 LAN** → turn on. (During this step the Mac is on the NAT/WAN side and will NOT see ROS topics — that's expected; we only need apt.)

- [ ] **Step 2: Confirm the robot reaches the internet.** The robot is now reachable over the cable at its IPv6 link-local OR, once Internet Sharing gives it a lease, `192.168.2.x`. From the Mac:

```bash
# Re-discover the robot on the cable (IPv6 link-local is stable per-MAC):
ping6 -c 3 ff02::1%en5 | grep 'bytes from' | grep -v "$(ifconfig en5 | awk '/inet6 fe80/{print $2}' | cut -d% -f1)"
# SSH via the link-local addr shown above, then test internet:
ssh -i ~/.ssh/id_ed25519 'ubuntu@fe80::da3a:ddff:fe7e:5caa%en5' 'ping -c1 -W2 8.8.8.8 && echo NET_OK'
```

Expected: `NET_OK`. If no internet, verify Internet Sharing is on and the cable link is up (`ifconfig en5` shows `status: active`).

- [ ] **Step 3: Install the bridge.**

```bash
ssh -i ~/.ssh/id_ed25519 'ubuntu@fe80::da3a:ddff:fe7e:5caa%en5' \
  'echo turtlebot4 | sudo -S apt-get update && echo turtlebot4 | sudo -S apt-get install -y ros-humble-foxglove-bridge'
```

Expected: apt completes; package installed.

- [ ] **Step 4: Verify install + capture the version.**

```bash
ssh -i ~/.ssh/id_ed25519 'ubuntu@fe80::da3a:ddff:fe7e:5caa%en5' \
  'source /opt/ros/humble/setup.bash; ros2 pkg prefix foxglove_bridge && dpkg -l ros-humble-foxglove-bridge | tail -1'
```

Expected: a prefix path prints and `dpkg` shows the installed version. **Record the version** — it decides the WS subprotocol string in Task 3.

- [ ] **Step 5: Turn OFF Internet Sharing, unplug the cable, re-cable Mac↔router LAN1.** Confirm the Mac is back on the LAN:

```bash
ifconfig en5 | grep 'inet '            # expect 192.168.0.x
ping -c2 192.168.0.100                  # expect 0% loss
```

Expected: Mac on `192.168.0.x`, robot reachable. No commit (robot state only).

- [ ] **Step 1: Write `tests/check_ws.sh`** (adapted from nav-trial; note the subprotocol is set in Task 3 after we know the version — default to `foxglove.sdk.v1`):

```bash
#!/usr/bin/env bash
# Foxglove WebSocket handshake probe. Usage: check_ws.sh http://192.168.0.100:8765
# Subprotocol: foxglove_bridge >=3.x uses "foxglove.sdk.v1"; older uses
# "foxglove.websocket.v1". Override with WS_SUBPROTOCOL if needed.
set -uo pipefail
BASE="${1:?usage: check_ws.sh <base-url>}"
SUB="${WS_SUBPROTOCOL:-foxglove.sdk.v1}"
RESP=$(curl -s -i -N --http1.1 --max-time 15 \
  -H "Connection: Upgrade" -H "Upgrade: websocket" \
  -H "Sec-WebSocket-Version: 13" \
  -H "Sec-WebSocket-Key: $(openssl rand -base64 16)" \
  -H "Sec-WebSocket-Protocol: $SUB" \
  "$BASE/" | head -5)
echo "$RESP" | head -1
if echo "$RESP" | head -1 | grep -q " 101 "; then
  echo "WS HANDSHAKE OK"; exit 0
else
  echo "WS HANDSHAKE FAIL"; exit 1
fi
```

Make executable: `chmod +x apps/tb4-teleop/tests/check_ws.sh`.

- [ ] **Step 2: Write `scripts/start_bridge.sh`** — launches the bridge on the robot, detached, and waits for the WS to answer:

```bash
#!/usr/bin/env bash
# Start foxglove_bridge on the robot over SSH (detached), then verify the WS.
set -euo pipefail
ROBOT="${ROBOT:-192.168.0.100}"
PORT="${PORT:-8765}"
SSH=(ssh -i ~/.ssh/id_ed25519 -o BatchMode=yes -o ConnectTimeout=12 "ubuntu@$ROBOT")

echo "Starting foxglove_bridge on $ROBOT:$PORT ..."
"${SSH[@]}" "source /opt/ros/humble/setup.bash; source /etc/turtlebot4/setup.bash 2>/dev/null; \
  pkill -f foxglove_bridge 2>/dev/null; sleep 1; \
  nohup ros2 launch foxglove_bridge foxglove_bridge_launch.xml port:=$PORT address:=0.0.0.0 \
  >/tmp/foxglove_bridge.log 2>&1 & echo started pid \$!"

echo "Waiting for WS handshake ..."
here="$(cd "$(dirname "$0")" && pwd)"
n=0
until "$here/../tests/check_ws.sh" "http://$ROBOT:$PORT" >/dev/null 2>&1; do
  n=$((n+1)); [ "$n" -ge 15 ] && { echo "BRIDGE DID NOT COME UP"; \
    "${SSH[@]}" 'tail -20 /tmp/foxglove_bridge.log'; exit 1; }
  sleep 2
done
echo "BRIDGE UP: ws://$ROBOT:$PORT"
```

Make executable: `chmod +x apps/tb4-teleop/scripts/start_bridge.sh`.

- [ ] **Step 2: Write the failing smoke test** `tests/smoke.sh` (run from the Mac; topic checks run ON the robot via SSH — no Mac-side ROS needed):

```bash
#!/usr/bin/env bash
# HIL smoke for tb4-teleop. Robot must be powered + on RobotWiFi + bridge running.
set -uo pipefail
ROBOT="${ROBOT:-192.168.0.100}"
PORT="${PORT:-8765}"
here="$(cd "$(dirname "$0")" && pwd)"
SSH=(ssh -i ~/.ssh/id_ed25519 -o BatchMode=yes -o ConnectTimeout=12 "ubuntu@$ROBOT")
SRC='source /opt/ros/humble/setup.bash; source /etc/turtlebot4/setup.bash 2>/dev/null'

echo "== 1/3 robot reachable =="
ping -c2 -t3 "$ROBOT" >/dev/null || { echo "ROBOT UNREACHABLE"; exit 1; }
echo OK

echo "== 2/3 bridge WS up =="
"$here/check_ws.sh" "http://$ROBOT:$PORT" >/dev/null || { echo "BRIDGE DOWN"; exit 1; }
echo OK

echo "== 3/3 /scan flowing =="
"${SSH[@]}" "$SRC; timeout 8 ros2 topic hz /scan 2>/dev/null | head -3" | grep -q "average rate" \
  || { echo "/scan NOT PUBLISHING"; exit 1; }
echo OK

echo "== 4/4 /cmd_vel accepts zero Twist (no motion) =="
"${SSH[@]}" "$SRC; timeout 5 ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist \
  '{linear: {x: 0.0}, angular: {z: 0.0}}' 2>&1 | grep -q 'publishing' && echo PUBOK" \
  | grep -q PUBOK || { echo "/cmd_vel PUBLISH FAILED"; exit 1; }
echo OK

echo "TB4-TELEOP SMOKE PASS"
```

Make executable: `chmod +x apps/tb4-teleop/tests/smoke.sh`.
