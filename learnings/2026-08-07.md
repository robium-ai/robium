- [none] figured-out-from-scratch <!-- id: lrn-0807-02 -->
  symptom: the active Codex task emitted `can't open file .../robium/0.2.1/
  hooks/scripts/stop_nudge.py` after Robium had been upgraded to plugin 0.2.2.
  root-cause: a running task retains the hook paths resolved from the plugin
  version active when that task started; upgrading the plugin does not rewrite
  those in-memory paths, and the old 0.2.1 cache entry lacked its hook scripts.
  fix: installed 0.2.2 with the complete hook bundle and added temporary
  forwarding shims at the exact cached 0.2.1 paths for the already-running
  task — check: Stop and PostToolUse shims executed successfully, the updated
  hook tests pass, and the installed plugin reports 0.2.2 enabled.
  dead-ends: reinstalling 0.2.2 alone; it fixes new tasks but cannot change
  hook paths already held by the current task.
  anchors: none (Codex plugin lifecycle behavior, not robotics skill content)
  source: Codex task 019fdcd0-419d-7df2-bcbd-ffb852054735 (robium, 2026-08-07)

- [foxglove] better-method <!-- id: lrn-0807-03 -->
  symptom: Foxglove organization layouts cannot give unaffiliated external
  users a zero-import, preconfigured live-robot view; a `layoutId` resolves a
  remotely saved personal or organization layout.
  root-cause: Foxglove layout sharing is account/organization scoped, while
  the current Lichtblick release accepts an HTTP(S) `layoutUrl` alongside
  `ds=foxglove-websocket` and fetches, installs, and selects that JSON layout
  in the browser without an organization account.
  fix: for unaffiliated external viewers who need a full Foxglove-style UI,
  consider self-hosted Lichtblick with a same-origin public layout JSON and a
  preconfigured launch URL — check: Lichtblick v1.27.1 source contains the
  `layoutUrl` parser and `fetchLayoutFromUrl` startup path, its Teleop panel,
  Foxglove WebSocket data source, and support for the bridge 3.x
  `foxglove.sdk.v1` subprotocol.
  dead-ends: Foxglove shared-layout deep links (organization membership
  required); Foxglove self-hosted embed (custom Enterprise agreement).
  anchors: foxglove#share-layout-json, foxglove#launcher-deep-link-share
  source: Codex task 019fdf40-259b-71d3-81d2-47657da8baed (robium, 2026-08-07)

- [foxglove] figured-out-from-scratch <!-- id: lrn-0807-04 -->
  symptom: Lichtblick looks like a drop-in open-source Foxglove replacement for
  an external operator dashboard, but two control-panel details differ in the
  current v1.27.1 release.
  root-cause: Lichtblick's Call Service panel has no editing-mode/button-only
  setting and always renders the JSON request and response; its Teleop panel
  stops the publish interval on pointer release but has no stop-on-release
  option and does not publish an explicit zero Twist.
  fix: use Lichtblick's Publish panel with editing mode disabled for compact
  fixed command buttons, put mode/map orchestration behind a robot-side
  supervisor, and require a robot-side velocity command timeout/watchdog for
  Teleop — check: verified directly in v1.27.1 `CallService.tsx`,
  `CallService/types.ts`, `Publish/settings.ts`, `TeleopPanel.tsx`, and
  `Teleop/buildSettingsTree.ts`.
  dead-ends: treating Call Service as the same compact button available in
  current Foxglove; relying on Lichtblick Teleop release alone to command zero.
  anchors: foxglove#teleop-panel-actions-limitation
  source: Codex task 019fdf40-259b-71d3-81d2-47657da8baed (robium, 2026-08-07)

  dead-ends: assuming a centralized Lichtblick extension marketplace or that
  Foxglove-compatible visualization extensions provide operator workflows.
  anchors: foxglove#teleop-panel-actions-limitation
