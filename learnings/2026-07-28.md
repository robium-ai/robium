# Learnings — 2026-07-28

## go2-locomotion — live WebRTC GUI + drive-the-trained-policy session (RunPod)

Goal: view the Go2 sim in the **full Isaac Sim GUI** streamed to a Mac, and drive the
**trained** policy with velocity commands. Huge infra-discovery session; nearly all of it is
"figured out from scratch" or "no skill fired" — high absorption value.

### [isaac-lab/isaac-sim] Full Isaac Sim GUI over WebRTC from a headless cloud pod — working recipe
- **Client** = *Isaac Sim WebRTC Streaming Client* (native app; macOS **aarch64** `.dmg` from
  `downloads.isaacsim.nvidia.com/isaacsim-webrtc-streaming-client-2.0.0-macos-aarch64.dmg`).
  Installable headlessly: `hdiutil attach` → copy `.app` to `/Applications` → `xattr -dr com.apple.quarantine`.
- The client exposes **Server IP + Signal port + Stream port + Resolution** fields — this is the
  key that makes it work behind RunPod's NAT.
- **Enable streaming**: Isaac Lab AppLauncher `--livestream 1` (public) + env `PUBLIC_IP=<ip>`; OR the
  full editor `/isaac-sim/isaac-sim.streaming.sh` (experience `isaacsim.exp.full.streaming.kit`, `--no-window`).
  Kit livestream settings live in `omni.kit.livestream.app.primaryStream`: signalPort=49100 (TCP),
  streamPort=47998 (UDP), publicIp, targetFps=60. **No bitrate setting exists** — bitrate is fully
  adaptive to QoS. (verified reading the extension.toml on the pod)
- **RunPod REMAPS ports** (internal 49100/47998 → external e.g. 30031/30032 or 14457/14458). In the
  client, set **Signal/Stream to the EXTERNAL mapped ports**, Server = pod public IP. That's what
  carries WebRTC through the NAT — the client's explicit port fields absorb the remap. (verified: video streamed)
- **Resolution MUST match a client-dropdown option** (720/1080/1440/4K). The app renders a FIXED
  size; if it ≠ what the client negotiated → `omni.kit.livestream.webrtc: Cannot stream video frame
  with resolution AxB that differs from CxD` → **black screen** (frames dropped). Force render size via
  **`--kit_args "--/app/window/width=1920 --/app/window/height=1080 --/app/renderer/resolution/width=1920 --/app/renderer/resolution/height=1080"`**
  — Isaac Lab 3.0 AppLauncher has **NO `--width/--height`** (`error: unrecognized arguments`); the valid
  passthrough is `--kit_args`. (verified: 720p default→1080p forced fixed the black screen)
- **"Grainy" = render RESOLUTION, not bitrate.** 720p upscaled on a Retina display looks grainy; native
  1080p is sharp. GPU sat at **0% util / <1GB** the whole time (empty/1-env scene) → tons of headroom to
  raise resolution for free. (user confirmed "much better" at 1080p)
- **"Slow/laggy" = pod DISTANCE.** ping RTT: **Romania ~200ms**, **US-Georgia ~80ms** (from SF). Not the
  L4, not settings. Redeploy in-region. `ip-api.com/json/<ip>` geolocates the pod fast.

### [isaac-lab/isaac-sim] Input forwarding — standalone script vs full editor (mutually exclusive with running a policy)
- Bare Isaac Lab scripts (`create_empty.py`, `play.py`) + `--livestream` stream **video but NOT input**
  → **view-only** (no mouse/keyboard; the interaction extensions never load — grep the log: no
  `omni.kit.manipulator.camera`). Symptom: "I see the full window but can't click/orbit anything."
- The **full editor** (`isaac-sim.streaming.sh` / `isaacsim.exp.full.streaming.kit`) DOES load them
  (`omni.kit.manipulator.camera … startup`) → fully interactive (mouse orbit + menus work). (verified)
- **BUT the full editor experience CANNOT run an Isaac Lab policy**: its editor timeline fights
  play.py's programmatic `env.step()` loop → env never finishes reset (`omni.physx.tensors: All physics
  information was deleted while being used by a tensor view class … simulationView invalidated`, repeating),
  **12-min hang, checkpoint never loads**. So **{trained policy + interactive-WebRTC + keyboard} is a
  three-way that can't all coexist** on this stack. (verified: full-experience run timed out; plain
  `--livestream 1` reached LIVE_SERVER_UP in ~2.5 min)

### [none/runpod] RunPod networking — the big time sinks, now mapped
- **The HTTP proxy `{podId}-{port}.proxy.runpod.net` can be silently DEAD**: TLS connects (Cloudflare
  fronts it) but the backend never responds → curl **HTTP 000**, even while the server returns 200 on
  `localhost:PORT` *inside* the pod. Do not rely on it.
- **SSH `-L` port-forwarding does NOT work** through RunPod proxy SSH (it's `docker exec`, not a real
  sshd) → `tunnel_http=000`. (verified)
- **Working exposure = public IP + a directly-exposed TCP port.** Non-root (`ubuntu`) can only bind
  **>1024** ports (can't use 22). A `connection refused` on a public port = mapping works, nothing
  listening (good); a *timeout* = no route. Bound a python TCP forwarder (49100→8888) to reach an
  internal server via the public IP when the proxy was dead.
- **Ports are FIXED at pod creation — cannot add later.** Expose everything up front. For "WebRTC view +
  web control panel" you need **TWO** public TCP ports (49100 signal + 48888 control) plus 47998/udp.
  Single-port pods force an either/or.
- **`dataCenterIds` in the REST create is a SUBSET** of the GraphQL datacenter list (US-CA-1/US-OR-* are
  NOT valid in REST; US-CA-2/US-WA-1 are). **L4-with-public-IP is scarce on the US west coast** →
  `500 "could not find any pods with required specifications"`. Pass a west-first array of ALL US DCs;
  it landed in **US-GA-2**. (`query { dataCenters { id } }` lists them; the REST 400 error body lists the valid enum)
- **File transfer to a pod = `runpodctl send/receive`** (relay, stays in the RunPod account, no public
  host): install the binary both ends (`github.com/runpod/runpodctl/releases/latest/download/runpodctl-<os>-<arch>`),
  `runpodctl send FILE` → prints `code`, `runpodctl receive CODE` on the pod. ~2–3 MB/s. Chunked-base64
  over the PTY is fine for small text (≤~8KB) but hopeless for a ~1MB binary. (verified: 984KB checkpoint moved cleanly)

### [isaac-lab] Reusing a trained checkpoint across pods AND minor versions ✓
- `outputs/go2_artifacts.tar.gz` (force-added to git, 22.5MB) holds 21 rsl_rl checkpoints + exported
  policy — **the durable checkpoint store** (survives pod termination; `outputs/`+`*.pt` are gitignored,
  so the tarball is the escape hatch). `model_1999.pt` (984KB) trained on last session's **3.0.0-beta2**
  **loaded cleanly into 3.0.0-beta2-post1** — no size mismatch (same task → same obs/action dims + MLP).
  Skips a 20–30 min retrain entirely.

### [isaac-lab] live_demo_patch.py portability fixes for a fresh pod
- `/workspace` is **read-only** for `ubuntu`; write generated `live_demo.py` + logs to **`/data`** (the
  volume). Retarget the patch's `LIVE = "/data/live_demo.py"`.
- `play.py` imports sibling module **`cli_args`** → running `live_demo.py` from `/data` throws
  `ModuleNotFound: cli_args`. Fix: `export PYTHONPATH=/workspace/isaaclab/scripts/reinforcement_learning/rsl_rl`.
- MJPEG frame params `640×360 / quality 55 / every-3rd-frame` were tuned for the **slow HTTP proxy**;
  on the **direct public IP** bump to `1280×720 / q80 / every-2nd` for a genuinely good in-page view.

### [none] Embedding Isaac Sim WebRTC into a custom webpage — NOT possible on the NGC image
- The image ships the **native** WebRTC client + the server extension but **no browser/JS WebRTC client**
  (searched `/isaac-sim` for html/js — none). NVIDIA's "web viewer" is a separate Docker-Compose piece.
  For an in-page sim view, use the **embedded MJPEG** (`env.render()` → `<img src=/stream>`) — it IS the
  real Isaac render, just JPEG not H.264/RTX.
