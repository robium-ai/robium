# 2026-07-25 — tb4-teleop (Orin console phase + base-discovery root cause)

## Create 3 base "invisible to the Pi" — the REAL fix, and a correction to a prior skill edit

- [ros2] **Root cause found: the Create 3 base's ROS 2 *application* gets stuck**, and the
  fix is **"Restart application" from the base's own web UI** (Application menu) — NOT any
  Pi-side DDS change. Symptom: `ros2 node list` shows no `/motion_control`, no
  `/battery_state`, base pings on `usb0` (`192.168.186.2`), and the base's **config is
  correct** (web UI → Application → Configuration: `RMW_IMPLEMENTATION=rmw_cyclonedds_cpp`,
  Domain 0, namespace empty, Fast DDS discovery server OFF — matching the Pi). Verified
  fix: base web UI → **Application → Restart application** → within ~20 s `motion_control:
  1`, `battery: 0.97`, robot drivable.
  - **Access the base web UI headlessly:** it's only on `usb0` (Pi-only). Tunnel it:
    `ssh -L 8888:192.168.186.2:80 ubuntu@<robot>` → open `http://localhost:8888` →
    Application → Configuration (read RMW/domain) and Restart application.
  - **Dead-ends that did NOT fix it (all Pi-side, ~10 attempts over 2 sessions):**
    `CYCLONEDDS_URI` unset (all-iface), explicit `usb0`/`usb0+wlan0`/`+DontRoute`, unicast
    `<Peers>` to 192.168.186.2 (multicast bypass), FastDDS discovery-server mode, matching
    Pi/base clocks, removing the Ethernet cable (extra iface), `POST /api/reboot`, and a
    full physical power-cycle (storage-mode → dock). None surfaced the base. Only the
    base-side **application restart** did. <!-- absorbed: 2026-07-25 (ros2 1.3.0) -->

## Networking (fixed-IP + rogue-DHCP)

- [none] **Two DHCP servers behind one "RobotWiFi" SSID.** The robot associated with the
  same AP the Mac uses (`98:DE:D0:FD:04:84`) but got a `10.0.0.165` lease (gateway
  `10.0.0.1`) from a *second* DHCP server (extender), while Mac/Orin got `192.168.0.x`
  (gateway `.1`) — same L2, different subnets → mutually unreachable. Fix: **static IPs**
  override the rogue lease. Robot `192.168.0.50` (netplan `dhcp4: false` +
  `addresses/routes/nameservers`), Orin `192.168.0.51` (`nmcli con mod RobotWiFi
  ipv4.method manual ...`). Both persist reboots.
- [none] **Wi-Fi MAC randomization** made the robot's hardware MAC (`d8:3a:dd…`) never
  appear in the router's DHCP table (showed a randomized `a8:e2:91…`) — don't search by
  hardware MAC; identify by hostname/SSH or just set static IPs.
- [none] Robot's RobotWiFi Wi-Fi latency is badly spiky (6 ms–1000 ms+), which made every
  SSH debugging command time out and background — a real teleop-quality concern, separate
  from the base issue.

  protocol work?) is retired. ✓ Worked as designed.
- [none] macOS Docker can't pass a USB webcam into a container (ustreamer is Linux/V4L2),
